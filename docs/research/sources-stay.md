# 근거 자료 — 숙소 후보(h-01~h-06)

확인 시점: 2026-09. 기준점(숙소)은 `data/taxonomy.json`의 `home` 필드 — lat 34.6704 / lng 135.5085 (시마노우치 2초메, OSM Nominatim 경계 중심).

## 조사 방식 고지

- 이 리서치는 이전 시도(반려됨)를 전면 재작성한 것이다. 이전 시도의 문제: (1) 좌표가 실제 위치와 최대 2957m까지 어긋남 (2) 모든 출처가 `google.com/maps/search/?api=1&query=...` 형태의 "이름만으로 조립한" 가짜 근거였음 (3) 확인되지 않은 사실("프런트 24시간 운영으로 확인됨")을 단정적으로 서술 (4) 존재 자체가 확인되지 않는 호텔(レム心斎橋)을 포함.
- 이번 조사에서는 세션의 WebSearch 호출 한도가 이미 소진된 상태로 시작했다(사전에 다른 조사에서 200/200 소진). 따라서 이번 조사는 전적으로 **WebFetch(공식 사이트 직접 접속) + OpenStreetMap Nominatim/Overpass API**만으로 수행했다. Google 웹검색·DuckDuckGo·Bing을 WebFetch로 우회 시도했으나 모두 캡차·JS 셸·무관한 결과만 반환해 실패했다.
- **좌표 검증 방법**: 모든 후보는 (a) Nominatim `q=<호텔 일본어명>&viewbox=135.40,34.78,135.60,34.60&bounded=1` 검색과 (b) Overpass API `tourism=hotel` 태그로 홈 좌표 반경 900m 내 전체 숙박시설을 뽑아 대조하는 두 가지 방법을 모두 사용해 교차 확인했다. 두 방법의 좌표가 수 미터~수십 미터 이내로 일치하는 것만 채택했다. Nominatim 요청 사이에는 1.2초 이상 간격을 두었고 User-Agent 헤더를 지정했다.
- **거리·도보시간 계산**: 하버사인 직선거리 × 1.3(시가지 보정) ÷ 75m/분. 이전 조사 문서(sources-shopping-stay.md)와 동일한 공식을 사용해 일관성을 유지했다.
- **가격(`budget`) 필드**: 실시간 요금 조회는 하지 못했다(부킹닷컴 등 예약엔진은 WebFetch로 안정적으로 열리지 않음). 각 호텔의 체인 등급·객실 타입을 근거로 한 **추정 범위**이며, 실제 예약 시점의 확정 요금과 다를 수 있다.
- **체크인/체크아웃 시각**: 홀리데이 인 오사카 난바만 공식 사이트에서 명시적으로 확인했다(IN 15:00 / OUT 11:00, 레이트체크인 자정까지). 나머지 5개 호텔은 공식 사이트에서 체크인/체크아웃 시각을 텍스트로 찾지 못했고(홈페이지에 실려 있지 않거나 별도 페이지가 404), 일본 도심 호텔의 통상적인 시각(IN 15:00 / OUT 11:00 전후)으로 추정 표기했다. 카드의 `caution` 필드에 이 사실을 명시하지 않은 대신 이 문서에 종합해 고지한다.

## 향후 재확인 필요 사항 (예약 전 반드시 확인)

1. 6개 후보 모두 "4인이 한 방에 묵는 정식 룸"이 실제로 존재하는지 공식 사이트 상세페이지 또는 예약엔진(부킹닷컴 등)에서 재확인 필요. 현재는 호텔 닛코 오사카의 "데럭스 패밀리룸"만 가능성이 있고, 나머지는 트윈룸 2개 예약을 기본 전제로 한다.
2. 6개 후보 모두 프런트 24시간 상시 근무 여부가 공식 사이트에 명시적으로 나와 있지 않다. 11/9(월) 06:45 출발이라는 일정상 매우 중요한 조건이므로, 예약 확정 전 반드시 전화 또는 예약 확인 메일로 "새벽 6시대 체크아웃/짐 인도가 가능한지"를 직접 문의할 것.
3. 짐 보관(체크아웃 후 당일 보관) 서비스 여부도 6개 후보 모두 개별 확인되지 않았다. 대부분의 일본 시티호텔이 일반적으로 제공하는 서비스이지만 이번 조사에서 공식 사이트 텍스트로 확인된 것은 아니다.
