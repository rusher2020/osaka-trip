## 4. 후보카드 데이터 모델

danang `CANDIDATE_DATA` 구조 계승, 필드는 오사카·성인 기준으로 교체.

```js
{
  id: "f-01",
  name: "미즈노",                 // 한글 표기
  nameJa: "美津の",                // 구글맵 검색용 원문 (필수)
  cat: "food-konamon",
  area: "dotonbori",
  lat: 34.6687, lng: 135.5013,
  budget: "1,500~2,500엔",
  hours: "11:00-22:00 (L.O. 21:30)",
  closed: "목",
  reserve: "불가·웨이팅",          // 예약필요 | 예약권장 | 워크인 | 불가·웨이팅
  seat4: true,                     // 4인 동시 착석 가능 여부
  why: "오코노미야키 노포, 마죠 야마이모야키",
  caution: "피크 60분 대기, 개점 직후 권장",
  walkFrom: "숙소 도보 9분",       // 시마노우치 기준 (전 카드 필수)
  placeId: "ChIJ...",              // Google Places 사진 fetch용
  checked: "2026-09",
  sources: ["url1", "url2"]
}
```

danang 대비 **신규 필드 5개**: `nameJa` · `reserve` · `seat4` · `walkFrom` · `placeId`.
이번 여행 성격(예약 전략 · 4인 착석 · 도보 판단 · 사진)상 전부 필수.

## 6. 리서치 검증 기준 (2026-09 기준)

카드마다 4단계 검증을 거치고, 통과한 것만 카드가 된다.

1. **존재 확인** — 구글맵/타베로그 현재 영업 여부. 폐업·이전·장기휴업 필터
2. **영업정보** — 2026년 기준 영업시간·정기휴무·라스트오더 (코로나 이후 단축 영업 다수)
3. **평판 교차** — 타베로그 점수 + 구글 평점 + 최근 6개월 리뷰. **한국 블로그 단독 근거 금지** (현지 인기와 괴리 큼)
4. **4인 실전성** — 4명 동시 착석 가능 / 예약 가능 여부 / 웨이팅 실태. 카운터 2~4석 노포는 제외하거나 `seat4: false` 명시

근거 URL과 확인 시점은 `docs/research/sources.md`에 전량 기록.

**재검증**: 출발 1주 전(2026-10-30경) 영업시간·휴무만 재확인. 별도 작업으로 분리.

## 7. 사진 전략 — Google Places Photos API (7-A)

Wikimedia에는 오사카 개별 식당·술집 사진이 사실상 없다(랜드마크만). 따라서 danang의
"공식 > Wikimedia > API" 우선순위를 그대로 쓰면 커버리지가 30% 미만으로 떨어진다.
오사카는 **Google Places Photos API를 주력**으로 한다.

- 각 카드의 `placeId`로 런타임 fetch, 세션 캐시
- `placeId` 확보: 리서치 단계에서 `nameJa` + 주소로 Places Text Search를 1회 돌려 수집 후 카드에 하드코딩. 런타임에는 검색을 돌리지 않는다 (요청 수·과금 절감)
- attribution 표기 (API 약관)
- 랜드마크(도톤보리 글리코, 츠텐카쿠 등)는 Wikimedia CC로 보완 → `assets/img/`

### 7.1 API 키 취급 (D-1 방식 · 배포 전제)

GitHub Pages는 정적 호스팅이라 서버가 없고, 브라우저에서 호출하는 키는 페이지 소스에
노출된다. 클라이언트 사이드 Google Maps/Places 키는 노출을 전제로 설계돼 있으며,
표준 방어책은 키를 숨기는 것이 아니라 **키를 제한하는 것**이다.

`config.js`를 **커밋한다** (danang은 gitignore했고, 그 결과 배포된 사이트에서는
Places 사진이 동작하지 않았을 가능성이 높다). 대신 아래 제한을 반드시 건다:

| 제한 | 설정 |
|---|---|
| HTTP 리퍼러 | `https://rusher2020.github.io/osaka-trip/*` 만 허용 (danang과 동일 계정 가정, repo명은 배포 시 확정) |
| API 제한 | Places API (New) 단일 허용. Directions·Geocoding 등 차단 |
| 쿼터 상한 | 일일 요청 한도 설정 (무료 크레딧 초과 과금 방지) |
| 키 분리 | **오사카 전용 키 신규 발급.** danang 키 재사용 금지 |

이 4개가 설정되기 전에는 `config.js`를 커밋하지 않는다.

## 10. 지도·라우팅 (danang과 최대 차이)

danang은 OSRM **자동차** 라우팅. 오사카는 렌터카를 쓰지 않으므로 부적합하다.
**하이브리드**로 교체한다.

| 구간 | 방식 |
|---|---|
| 도보 | OSRM foot 프로파일 실선 라우팅 + 소요분. 미나미 내부는 거의 전부 여기 해당 |
| 지하철 | 라우팅 불가 → `TRANSIT_TIMES` 사전 계산 테이블. 역-역 직선 + **노선색**(미도스지=빨강, 사카이스지=갈색 등) + 소요분·환승 라벨 |
| 공항 | 난카이 공항급행/라피트 고정값 |

모든 카드에 시마노우치 기준 도보 분(`walkFrom`)을 박아, 지도를 열지 않고 카드만으로
판단 가능하게 한다.
